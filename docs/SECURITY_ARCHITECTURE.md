# RaceOne — 平台安全架構總覽（Security Architecture Overview）

> **目的**：說明 RaceOne 平台的安全設計**原則與機制**（高層級），不含實際金鑰、憑證、Policy 原始碼或部署設定等敏感細節。
> 用於讓觀看者理解平台對資安與資料隔離的重視。

---

## 🔐 安全設計總原則

| 原則 | 說明 |
|------|------|
| **零信任 (Zero Trust)** | 即使是同平台使用者，也預設不信任，僅授予最小必要權限 |
| **防禦縱深 (Defense in Depth)** | 多層防禦，單一層被繞過仍有後援 |
| **預設拒絕 (Default Deny)** | 未明確授權的操作，一律拒絕 |
| **最小權限 (Least Privilege)** | 每種角色僅能存取其業務範圍內的最小資料 |
| **資料最小化** | 僅收集與處理業務所需的資料 |
| **可稽核 (Auditable)** | 關鍵操作皆有紀錄可追溯 |

---

## 🛡️ 多層防禦模型（Defense in Depth）

```
┌───────────────────────────────────────────────────────────┐
│  Layer 1: 網路與入口                                       │
│  ├─ Cloudflare DNS / CDN / WAF 資安防護                    │
│  ├─ HTTPS 加密傳輸（憑證自動管理）                        │
│  └─ 受保護路由需登入（未登入會重新導向登入頁）             │
├───────────────────────────────────────────────────────────┤
│  Layer 2: 應用認證與授權（Next.js / Server）               │
│  ├─ 基於 JWT 的身分驗證機制                                │
│  ├─ 路由層守衛：後台路徑需有效 Session                    │
│  └─ 伺服器端再次驗證使用者身分（非僅信任前端 Cookie）      │
├───────────────────────────────────────────────────────────┤
│  Layer 3: 資料庫強制隔離（RLS）                             │
│  ├─ Row-Level Security：每列資料依權限過濾                │
│  ├─ 租戶/賽事/使用者三層隔離維度                           │
│  └─ 即使直連資料庫工具，權限同樣生效（無法繞過）          │
└───────────────────────────────────────────────────────────┘
```

> **關鍵**：前三層皆可被技術熟練者嘗試繞過，但資料庫層的 RLS 是最後防線——它讓權限成為資料本身的一部份，而非依賴應用程式的遺忘與否。

## 🏢 多租戶資料隔離

平台為**多租戶白牌架構**，不同組織（賽事主辦方）的資料嚴格隔離：

- **租戶層**：`tenants` 為根，每個使用者與賽事都歸屬於一個租戶
- **賽事層**：賽事資料（報名、交易、補給站等）依賽事/租戶隔離
- **使用者層**：使用者設定檔與個人報名資料各自管控

> 隔離透過資料庫層強制執行，從「查詢語法」層面防止跨租戶資料洩漏。

## 🔑 角色權限設計（RBAC）

平台提供多種角色，各角色的存取範圍不同（例如財務角色方能查看收支 / 預算，內容編輯角色則否）。

權限管控體現在三個層面：
1. **UI 層**：依角色隱藏無權限的入口，降低誤點與挫折
2. **路由層**：後台頁面需登入驗證
3. **資料庫層**：資料查詢依角色過濾（最嚴格）

> 無論 UI 如何，資料庫層始終是最終裁決者。

## 🔒 金鑰與機密管理

開發與部署遵循機密保護原則：

| 事項 | 做法 |
|------|------|
| 環境變數 | 金鑰/Token 放環境變數，不入原始碼 / Git |
| `.env.example` | 只放 placeholder 範例值，不放真實值 |
| 前端曝光 | `NEXT_PUBLIC_*` 僅放公開 Key；含機密的 Key 僅伺服器端持有 |
| Git 忽略 | `.gitignore` 排除 `.env*`、憑證、快照等 |

## 📝 可稽核性

關鍵操作（含 Bot 指令觸發、通知發送、後台變更）有紀錄可追蹤，便於：
- 異常行為調查
- 操作還原決策參考
- 團隊協作的透明度

---

## 🧪 安全測試與品質

每個 release 皆通過「Release QA Gate」的品質檢查（含公開頁 / 受保護頁 / 資料庫 / 使用者模擬），確保功能與安全在每次變更後依然穩固。
